# Design

The full scope and design doc lives in the project's Claude Doc "CCNA Simulator: Scope and Design". Summary:

- **Goal:** a CCNA 200-301 v2.0 study tool that also works as a portfolio demo (static site, no server).
- **Stack:** TypeScript monorepo; pure engine package; React + Vite UI; React Flow canvas; xterm.js console; Zustand; Vitest and Playwright; GitHub Pages.
- **Phases:** 1 core engine (switching, VLANs, trunks, SVIs, static routing, ping/traceroute, CDP/LLDP, show commands, capture panel) · 2 study mode (labs, grader, progress) · 3 portfolio polish · 4 protocol expansion (OSPF, DHCP, NAT, ACLs, IPv6, PVST+/Rapid PVST+, EtherChannel, port security, HSRP, VRRP, GLBP, QoS and file transfer done; DNS to come) · 5 security and operations.

## Engine rules

1. The engine has no DOM or React imports. Anything the UI shows comes from engine state.
2. Devices talk only through `Topology.transmit`; delivery is a scheduled event.
3. Every protocol feature ships with a Vitest spec written as a tiny lab.
4. CLI output mirrors real IOS formatting closely enough that study notes and real show output match.

## Study mode

- **Lab format:** `packages/engine/src/labs/types.ts`. A lab has a briefing, an optional addressing table, a starting topology, objectives, a model answer per device and a debrief. It is tagged with its blueprint domain and objectives.
- **Grader:** `LabRun` builds the lab's topology and keeps devices keyed by their lab hostname, so a learner renaming a device does not break grading. Checks are pure reads of engine state, except `ping`, `traceroute` and `connect`, which send traffic and so only run on "Check my work". Quiz objectives are graded from the learner's answer.
- **Progress:** `Progress` holds pure state transitions (start, check, hint, solution); the web app persists the store in `localStorage` under `ccna-sim:progress:v1`.
- **Tests:** every lab must start unsolved and be fully solved by typing its model answer into the real CLI.
- **Gaps:** Lab state is not saved mid-attempt; leaving a lab resets it. Domain 4.7 has port security, DHCP snooping, Dynamic ARP Inspection and IP Source Guard labs; domain 5.0 has syslog, NTP and a packet-capture troubleshooting lab. Domain 1.5 has five wireless labs; 4.1 has SSH and AAA labs; 5.0 adds SNMP, RESTCONF and Ansible labs. 3.4 now has VRRP and GLBP labs, 4.7 storm control and RA guard, and 4.2 configuration backups over TFTP, FTP and SCP. QoS is not a numbered v2.0 objective, so its two labs are filed under domain 4.0 as a whole. NETCONF needs engine support first.

## Protocols (Phase 4, first pass)

- **Convergence:** `Topology.converge()` runs after every CLI command, cabling change and lab setup. It runs rounds of `tick()` (send hellos, retry DHCP) then `settle()` (expire neighbors, elect, originate LSAs, run SPF) until nothing changes. One round stands for one hello interval, so the simulator shows the converged state straight away instead of making learners wait 40 seconds.
- **OSPF:** single-area OSPFv2 (`packages/engine/src/routing/ospf.ts`). A neighbor not heard in a round is dead. Database exchange is simplified: a DBD carries full LSAs and the adjacency goes straight to FULL, so EXCHANGE and LOADING are not visible. LSAs do not age; a flush leaves a tombstone so stale copies cannot come back. Timer and mask mismatches are silent, as on IOS; area mismatches and duplicate router IDs are logged.
- **DHCP, NAT, ACLs** (`packages/engine/src/services`): DHCP runs DORA with retransmits (routers drop the packet that triggers ARP, as on IOS), relays through `ip helper-address` using giaddr, and gives PCs an APIPA address when no server answers. NAT handles static, pool and overload (PAT, keyed on ICMP id or TCP port) and answers ARP for its global addresses. ACLs are evaluated inbound before routing and outbound after; a deny returns an ICMP unreachable, and outbound ACLs never filter the router's own traffic.
- **IP pipeline:** receive, ARP and DHCP, ACL in, OSPF, NAT outside-to-inside, then local delivery or forwarding (TTL, route lookup, NAT inside-to-outside, ACL out).

## Protocols (Phase 4, second pass)

- **Spanning tree** (`packages/engine/src/switching/stp.ts`): one instance per VLAN for both `pvst` and `rapid-pvst`. Each round, designated ports send BPDUs and `settle` elects the root by (root ID, cost, bridge ID, port ID) and assigns root, designated, alternate and backup roles. A BPDU not heard in a round counts as lost and max age is 20 hops. There is no proposal/agreement handshake and no listening/learning timers, so a port moves straight to forwarding or blocking; the two modes differ only in the name shown. Until the first settle every port forwards; a port that comes up later waits one round unless it is PortFast. PortFast, BPDU guard (err-disable) and root guard (root-inconsistent) are supported; loop guard, MST and per-VLAN port cost are not. MAC tables are flushed when the topology changes.
- **EtherChannel** (`packages/engine/src/switching/etherchannel.ts`): LACP and PAgP PDUs are sent per member each round. A member bundles when the modes negotiate, its L2 settings match the port-channel, and it reaches the same partner as the other members; otherwise it is suspended and silent. Mode `on` does not check the far end. Frames are spread with a src-dst-mac hash. STP sees the port-channel as one port (cost 3, port number 64+N). There is no L3 EtherChannel.
- **Port security:** checked on ingress before STP and MAC learning. Supports maximum, static, dynamic and sticky addresses and the three violation modes. Dynamic addresses are cleared when the port goes down; `shutdown` clears err-disable. There is no address aging, no trunk-port security and no errdisable recovery timer.
- **IPv6** (`packages/engine/src/ipv6/stack.ts`): routers and PCs only (no switch SVIs). Global, EUI-64 and link-local addresses, solicited-node multicast, NS/NA, RS/RA and SLAAC on PCs, with the router's link-local address as the PC gateway. Routers forward and advertise only with `ipv6 unicast-routing`. Static routes resolve recursively; a link-local next hop needs an exit interface. There is no DAD, DHCPv6 or OSPFv3, neighbors never go stale, pings to link-local addresses are not supported, and routers have no `ipv6 address autoconfig`.
## Protocols (Phase 4, third pass)

- **HSRP** (`packages/engine/src/routing/hsrp.ts`): routers only, versions 1 and 2 (UDP 1985 to 224.0.0.2 or 224.0.0.102). Each round, Active and Standby send hellos and `settle` elects by priority, then the highest interface address. A group coming up spends one round in Listen, so a peer already Active keeps the role unless the newcomer has preempt and a higher priority. Speak is not shown separately and there are no hello/hold timers, authentication, MD5, IPv6 groups or `standby use-bia`. Tracking only follows the line protocol of an interface, and the decrement defaults to 10. The Active router answers ARP for the virtual IP with the virtual MAC and accepts frames sent to it. VRRP and GLBP are below.
- **DHCP snooping** (on `Switch`): checked after STP on every access or trunk port. Untrusted ports drop server messages (OFFER, ACK, NAK) and client messages whose chaddr differs from the source MAC. A trusted ACK creates a binding on the client's port (found from the MAC table); a RELEASE removes it. Option 82 is inserted on untrusted ports unless `no ip dhcp snooping information option` is set, and an IOS DHCP server or relay drops such requests unless `ip dhcp relay information trusted` or `trust-all` is configured, which reproduces the classic "snooping broke DHCP" fault. `ip dhcp snooping limit rate` is stored and shown but not enforced, and there is no binding database or lease expiry. The snooping bindings also feed Dynamic ARP Inspection and IP Source Guard (below).
- **Device access** (`packages/engine/src/services/management.ts`, `packages/engine/src/cli/remote.ts`): telnet and SSH open a nested `CliSession` on the target, reached through the real IP path (so ACLs and routing apply). SSH is a TCP check on port 22 plus a login; there is no encryption, key exchange or host key prompt. Port 22 listens only once RSA keys exist, and SSH requires `login local`. `transport input` decides which of ports 22 and 23 listen. `enable secret` uses a fixed fake MD5 hash; `service password-encryption` uses real type 7 encoding. There are no AAA, privilege levels other than 1 and 15, exec timeouts (stored only) or access-class.
- **NTP and the clock** (`packages/engine/src/services/ntp.ts`): each device's clock is 1 March 1993 plus virtual time, plus any offset from `clock set` or NTP. A client asks its servers each round and takes the first reply, at the server's stratum plus one; it loses sync when a round passes with no reply. There is no polling interval, no offset filtering, no authentication, no peer mode and no summer time. `clock timezone` changes only how the time is shown. NTP is no longer in blueprint v2.0, so its lab is filed under 5.6 (syslog) for the timestamps.
- **CDP and LLDP** (`packages/engine/src/services/discovery.ts`): routers and switches advertise on every physical port each round to the CDP or LLDP multicast MAC; switches consume these frames and never forward them. A neighbor not heard in a round is removed, so holdtimes count down only in the display. CDP is on by default and LLDP off. CDP logs a native VLAN mismatch on trunks once per neighbor. There is no CDP version 1, no VTP domain or duplex in CDP, no LLDP-MED and no `cdp timer` or `lldp timer`.

## Security and operations (Phase 5)

- **Dynamic ARP Inspection** (`packages/engine/src/switching/arp-inspection.ts`): enabled per VLAN (`ip arp inspection vlan`), inspected on untrusted ports after DHCP snooping. An ARP frame passes when an ARP ACL permits it, or its sender IP/MAC matches a DHCP snooping binding; otherwise it is dropped and logged (once per source per second). Optional `validate` checks (src-mac, dst-mac, ip) follow IOS: each `validate` command replaces the previous set. Rate limiting counts arrivals per burst interval and err-disables the port over the limit (default 15 pps on untrusted ports). ARP poisoning is modelled by a PC's `arpspoof` tool sending gratuitous ARP; a receiver with a conflicting entry for its own address logs `%IP-4-DUPADDR` and keeps its entry. There is no ARP probe logging, no per-MAC ACL beyond IP+MAC pairs, and the rate window uses virtual time, which only advances while traffic flows.
- **IP Source Guard** (`packages/engine/src/switching/source-guard.ts`): `ip verify source` on a port drops IPv4 frames whose source IP (and MAC, with `port-security`) is not a snooping binding or a static `ip source binding` for that port and VLAN. DHCP is always permitted so a client can obtain the lease that creates its binding. It is inactive on a trusted port or a VLAN without snooping. Trunk ports filter in their native VLAN only (a simplification). Err-disable recovery (`errdisable recovery cause/interval`) brings a port back once its timer passes during convergence.
- **Packet capture** (`packages/engine/src/capture/`): the topology already records every frame on the wire in `Topology.trace`; capture numbers each frame, tags it with the link, and caps the buffer at 20,000. `dissect`/`summarize` turn a frame into Wireshark-style rows and a layer tree, and `compileFilter` parses a small display-filter grammar (protocol words, `ip.addr`/`eth.addr`/`vlan`/`tcp.port` comparisons, `&&`/`||`/`!` and parentheses). The web panel opens from a cable click; it reads engine state and performs no new simulation.

## Management, AAA and wireless (Phase 6)

- **AAA** (`packages/engine/src/services/aaa.ts`, `aaa-server.ts`): `aaa new-model` with named and default method lists for login authentication, EXEC authorization and EXEC accounting; methods are server groups, `local`, `line`, `enable` and `none`, tried in order. A method falls through only on an error (no reply, no such server); a reject ends the login, as on IOS. RADIUS (UDP 1812/1813) and TACACS+ (TCP 49) carry the username and password in clear fields with the shared secret alongside; a key mismatch is silently dropped by the server, which logs it, so it looks like a timeout. Servers are the Linux `Server` device's built-in AAA daemon (`aaa user`/`aaa client`/`aaa log`), a stand-in for ISE. There is no command authorization, no CoA and no per-command accounting.
- **SNMP** (`packages/engine/src/services/snmp.ts`, `snmp-mib.ts`): an agent on routers and switches with v1/v2c communities (ro/rw, optional standard ACL) and v3 groups and users (noAuth, auth, priv). A small MIB-II subset (system, interfaces, ipAddrTable) answers get, get-next and walk; `sysName`, `sysContact`, `sysLocation`, `ifAdminStatus` and `ifAlias` are settable through rw access. linkUp/linkDown traps go to `snmp-server host` targets. v3 authentication and privacy are checked by comparing the configured algorithm and password, not by HMAC or encryption; a capture shows v3 payloads as encrypted. The manager is `snmpget`/`snmpgetnext`/`snmpwalk`/`snmpset` on the Server, and traps land in `/var/log/snmptrapd.log`.
- **RESTCONF** (`packages/engine/src/services/restconf.ts`): `ip http secure-server` plus `restconf` opens TCP 443. `curl` on the Server sends GET, PATCH, PUT, POST and DELETE with HTTP basic auth checked against a privilege 15 user (from AAA when it is on, otherwise the local database). It covers `ietf-interfaces` (configuration and state, with ietf-ip addresses) and the hostname from `Cisco-IOS-XE-native`; other paths answer 404. There is no TLS, no XML, no NETCONF and no YANG library beyond the root resource.
- **Ansible** (`packages/engine/src/services/ansible.ts`): `ansible-playbook` on the Server parses INI inventories and YAML playbooks (written with a `cat > file <<EOF` heredoc) and runs `cisco.ios.ios_command`, `ios_config` (lines and parents, idempotent against the running config), `ios_facts` and `debug` over the simulated SSH, with `ansible-playbook`-style output and recap. There are no roles, loops, handlers, conditionals or Jinja beyond `{{ var }}`.
- **Wireless** (`packages/engine/src/devices/wlc.ts`, `ap.ts`, `wireless/wifi.ts`): an AireOS-style WLC, lightweight APs in local mode and laptops with a Wi-Fi NIC. APs get an address by DHCP or statically, then discover controllers by broadcast, a primed primary-base, or DHCP option 43, and join over CAPWAP (UDP 5246 control, 5247 data). Echoes run each round; a missed echo or a down uplink drops the join and the AP's clients. Split MAC: the AP tunnels every client frame to the WLC, which runs authentication (open, WPA2-PSK, WPA3-SAE, WPA2-Enterprise with RADIUS) and bridges client traffic onto the VLAN of the WLAN's interface over its trunk. The PSK 4-way handshake and SAE are reduced to comparing a hash of the SSID and passphrase; 802.1X is one PEAP-like credentials exchange against RADIUS. Radio is idealised: every client hears every AP, there is no RF, signal strength, roaming, band steering beyond preferring 5 GHz, FlexConnect or autonomous APs. DCA picks the least-used of channels 1/6/11 and 36/40/44/48. The web app adds a cut-down WLC GUI (WLANs, APs, clients) that runs the equivalent CLI commands and shows them.

- **CLI:** `interface range` runs each command on every interface in the range. The command matcher prefers the candidate with more literal keywords, then more exactly typed keywords, when abbreviations are ambiguous.

## Redundancy, traffic control, QoS and file transfer (Phase 7)

- **VRRP** (`packages/engine/src/routing/vrrp.ts`): version 3 for IPv4 on routers (IP protocol 112 to 224.0.0.18, virtual MAC 0000.5e00.01XX). Only the master advertises, from the virtual MAC. A router whose interface address is the virtual IP is the owner (priority 255). Preemption is on by default. A backup that hears no master in a round takes over; there is no skew time, so with three or more routers two backups can both become master for one round before the better one wins. There is no object tracking, authentication, timers or IPv6 VRRP.
- **GLBP** (`packages/engine/src/routing/glbp.ts`): UDP 3222 to 224.0.0.102. The AVG is elected like HSRP (priority, then address; preemption off by default) and hands each member one of up to four virtual forwarders (MAC 0007.b4GG.GGFF). It answers ARP for the virtual IP round-robin (default), weighted, or host-dependent. When a forwarder's owner stops sending hellos the AVG takes the forwarder over, and gives it back when the owner returns. There are no redirect or timeout timers, no weighting thresholds with tracking, and no preemption delay.
- **Storm control** (`packages/engine/src/switching/storm-control.ts`): every link is treated as carrying at most 1,000 frames per second, so a level of 1.00% is 10 frames per second; `pps` levels are exact. Broadcast, multicast and unknown-unicast frames are counted per port per one-second interval of virtual time. Above the rising level the excess is dropped until an interval ends under the falling level; `action shutdown` err-disables the port and `action trap` sends an SNMP trap. PCs have a `flood` tool to generate storms. Real thresholds depend on link speed and frame sizes; this keeps storms visible with a few hundred frames.
- **RA guard** (on `Switch`): `ipv6 nd raguard policy` with `device-role host` or `router`, attached per port. A port with a host policy (including the implicit `default` policy from `attach-policy` without a name) drops router advertisements arriving on it. There is no RA inspection by prefix, hop limit or source list, and no DHCPv6 guard. PCs have `fake_router6` to send rogue advertisements.
- **QoS** (`packages/engine/src/services/qos.ts`): DSCP is a field of every IPv4 packet; PCs can mark their own traffic (`ping -v <tos>`, or a lab's `dscp`). Routers have the MQC: class maps (match-any or match-all on DSCP, precedence, ACLs, a handful of protocols, or any), policy maps with `set dscp`/`set ip precedence`, `police` (a token bucket with estimated packet sizes and transmit, drop or re-mark actions), `priority`, `bandwidth`, `shape average` and `fair-queue`, attached with `service-policy input|output`. Input policies cannot queue, and queuing reservations are checked against the interface bandwidth, as on IOS. Queuing is configured, validated and shown, but links never congest, so it never reorders or drops traffic. Output policies apply to forwarded traffic only. Catalyst `mls qos` makes every port untrusted (DSCP rewritten to 0) until `mls qos trust dscp`; CoS is not modelled, so `trust cos` keeps the marking only on trunks.
- **File transfer** (`packages/engine/src/cli/commands-files.ts`, `IpDevice.transfer`): IOS `copy` between running-config, startup-config, flash and TFTP, FTP, SCP or SFTP servers, with the IOS prompts and URLs (`tftp://host/file`, `ftp://user:password@host/file`). A transfer is one request and one reply: TFTP over UDP 69; FTP (TCP 21) and SCP/SFTP (TCP 22) after a TCP connection. Captures show FTP logins in clear text and SCP/SFTP as encrypted SSH. The Linux `Server` always serves TFTP and serves FTP, SCP and SFTP once it has an account (`adduser`); transfers are logged in `/var/log/xferlog`. Copying into running-config merges the file line by line. The startup config is saved and shown, but there is no reload, so it never replaces the running config. Flash holds a fixed IOS image plus copied files.
